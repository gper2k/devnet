# BitPlus.Web.Site Views/Content (컨텐츠 형식별 파샬뷰)

컨텐츠 규칙(`ContentRule`)의 **형식(`ContentTypes`)** 마다 폴더를 두고, 그 안에 해당 형식의 화면을 파샬뷰로 둡니다.
형식은 "그 컨텐츠를 보여 주는 뷰의 모양이 달라지는 것"을 기준으로 나눈 것입니다. (공지 상단 고정, 비공개 같은 것은 화면 모양이 아니라 규칙의 옵션/기능으로 처리하므로 형식이 아닙니다.)

## 요청 흐름

`/content`(규칙 번호 없음) → `ContentController.Portal()` — 컨텐츠 포탈(`Views/Content/Portal.cshtml`): 사이드 패널 + 위젯 페이지 `portal`.
`/content/menu/{메뉴 키}` → `ContentController.MenuPortal()` — 메뉴별 컨텐츠 포탈: 같은 화면이되 위젯 배치는 `portal@{메뉴 키}`(따로 저장한 적 없으면 `/content` 배치), 사이드 패널은 그 메뉴를 연결 메뉴로 씀(트리 루트, 사이드 위젯 `side@{메뉴 키}`). 메뉴가 없거나 사용 중이 아니면 404, 메뉴 접근 권한이 없으면 401/403.

규칙 번호가 있는 `/content/{ruleNo}/{view?}` → `ContentController.Index(ruleNo, view)` (`Controllers/ContentController.cs`, 뷰 컨트롤러; REST API 는 `Controllers/API/ContentController`)

1. `ruleNo` 로 컨텐츠 규칙을 찾습니다. 없거나 비활성(`Enabler=false`)이면 404.
2. 규칙의 형식(`Type`) 폴더 `Views/Content/{형식}/` 에서 파샬뷰를 고릅니다.
   - `view` 가 없으면 **`Index.cshtml`** (각 형식의 첫 화면, 모든 형식 공통 이름).
   - `view` 가 있으면 그 이름의 뷰. 예) `/content/1/list?page=1` → 1번 규칙의 형식 폴더에서 `List.cshtml` (쿼리 문자열은 뷰가 `Request.Query` 로 읽음).
3. 그 형식 폴더에 해당 뷰가 없으면 404.
4. `Views/Content/Index.cshtml`(페이지 틀, 기본 레이아웃 — 형식 폴더의 `Index.cshtml` 과는 다른 파일)이 선택된 파샬뷰를 `<partial>` 로 끼워 넣습니다. 모델은 `ContentPageModel`(`RuleNo`, `Title`, `Type`, `View`).

규칙:
- 뷰 파일 이름은 프로젝트의 다른 뷰처럼 PascalCase(`Index`, `List`, `View`…)입니다. 요청의 `view` 는 대소문자를 가리지 않고 첫 글자를 대문자로 바꿔 찾습니다.
- `view` 는 영문으로 시작하는 영문·숫자·밑줄 32자 이내만 허용합니다 (경로 조작 방지, `ContentController.ViewNameRegex`).
- 라우트 값 이름 `action` 은 MVC 예약어라 `view` 로 받습니다.
- 규칙 권한(`ContentPermission`, `Models/ContentPermission.cs`): **관리자** = 관리자 정책(`Manager`)·컨텐츠 관리자 정책(`ContentManager`)을 만족하거나 규칙의 `Manager` 모드 대상에 속하는 사용자 — 읽기·쓰기 모두 가능.
  그 밖에는 규칙에 등록된 대상(권한 행)이 없으면 누구나 읽을 수 있고 **로그인** 사용자는 누구나 쓰기·댓글을 할 수 있으며, 대상이 등록돼 있으면 모드마다(읽기·쓰기·댓글) 그 모드가 체크된 대상에 속해야 합니다. 쓰기만 체크하고 읽기를 체크하지 않은 대상은 글은 쓰지만(쓰기 화면은 쓰기 권한만 확인) 목록을 읽지는 못합니다. 비회원은 글을 쓸 수 없습니다.
  읽을 수 없는 규칙과, 쓸 수 없는 사용자가 연 `write` 화면은 비로그인 401·로그인 403 (오류 페이지). 글 단위 읽기 권한(`ReadRule`)·`Answer` 모드 검사는 아직 없습니다.
- 목록 화면(`Index`·`List`)은 컨트롤러가 공개된 글(표시 + 게시 + 승인, 게시 기간 안, 관리자는 모두)을 공지 먼저 최신순으로 한 페이지(`?page=` 1부터, `?size=` 페이지당 글 수 10/20/30, 기본 10) 불러와 모델(`Items`/`Page`/`Total`)에 채웁니다.
- **게시판 설정** `/content/manage/{ruleNo}` 와 신규 등록 `/content/manage`(규칙 번호 없음, 형식은 `?type=`, 생략하면 일반): `ContentController.Manage` 가 그 규칙 형식 폴더의 `Manage.cshtml`(현재 `Default/Manage.cshtml` 만 있음)을 페이지 틀 안에 보여 줍니다. 규칙 설정은 규칙 관리자(`ContentPermission.IsAdmin`), 신규 등록은 관리자 정책·컨텐츠 관리자 정책을 만족하는 사용자만 열 수 있고 아니면 401/403, 없는 형식·규칙은 404. 비활성 규칙도 열 수 있습니다. 옛 경로 `/content/{ruleNo}/manage` 는 새 경로로 리다이렉트합니다. 설정 항목이 형식마다 달라 형식 폴더마다 자기 Manage 뷰와 형식 이름이 붙은 설정 API 를 둡니다. 목록 화면의 설정 버튼(관리자에게만 보임)으로 들어갑니다. 일반 형식 탭 — 기본 사항(제목 다국어·파일 규칙·활성화, 형식은 바꾸지 않음) / 권한(한 목록으로 통합: 항목 = 유형·이름·읽기/관리/쓰기/답글/댓글 체크 상자·삭제 버튼. 체크마다 모드별 행(`Read`/`Manager`/`Write`/`Answer`/`Comment`)으로 저장하고 항목마다 1개 이상 체크를 유지(마지막 체크는 끌 수 없음, 등록 의미가 없으므로). 하단의 사용자/그룹/그룹(자식 포함)/역할을 누르면 선택 모달이 떠서 고른 대상을 읽기·쓰기·답글·댓글 체크 상태로 추가; 비우면 제한 없음) / 승인자(별도 탭: 게시 승인자 사용자 목록 — 하단 User 를 누르면 사용자 찾기 모달, 항목 끝 삭제 버튼, 번호가 승인 순서이고 항목을 드래그 앤 드롭으로 옮겨 순서를 조정하면 저장 시 그 위치값이 순서(`SortNo`)로 저장됨; 승인 절차 자체는 아직 없음). **저장되는 값**: 제목·파일 규칙·활성화는 규칙 컬럼, 카테고리는 규칙 `Category` 컬럼(세미콜론 연결 문자열), 맞는 컬럼이 없는 값은 규칙 속성(Property)으로 저장합니다 — 상단/하단 영역 HTML(정제한 HTML, `TopHtml`/`BottomHtml`, 에디터 이미지 소유자 `content.rule`/규칙 식별키로 등록·정리), 승인 옵션과 기능 옵션 체크 상자 전부(`data-opt` 키 → `{키: 불리언}` 사전 하나를 JSON 으로 묶은 속성 `Options`), 게시 승인자는 승인자 테이블(`SortNo` = 목록 위치). 옵션 키를 추가하려면 체크 상자에 `data-opt` 만 붙이면 됩니다(저장된 적 없는 키는 화면의 기본 체크 유지, 키는 영문으로 시작하는 영문·숫자·밑줄 64자 이내·최대 100개). 그 밖의 속성은 이 화면에서 건드리지 않고 그대로 둡니다. 값은 `api/content/default/{ruleNo}/settings`(GET 조회, PUT 저장; 규칙 관리자만, 일반 형식 규칙만)와 신규용 `api/content/default/settings`(GET 기본값, POST 등록)로 읽고 쓰며, 저장하면 그 게시판 목록으로 이동합니다.
- 메뉴에서 컨텐츠로 연결하는 경로는 `/content/{RuleNo}` 입니다 (컨텐츠 규칙 목록 ⋮ → 메뉴 추가).

글쓰기(`Default/Write.cshtml`)의 **첨부 파일** 영역: 게시판 파일 규칙을 `GET api/content/file` 로 읽어 사용·업로드 권한이 있을 때만 나타난다. "파일 선택" 버튼으로 고르면 파일마다 차례로 업로드(`common.upload`, 진행률)하고 아래 목록(ul)에 파일명(넘치면 말줄임) / 전송 상태(진행률, 가장 넓음) / 용량 / 삭제 버튼 순으로 한 줄씩 보인다. 이번 작성에서 올린 파일을 지우면 바로 삭제, 이미 등록된 파일은 저장할 때 함께 삭제한다. 새 글은 `api/content/draft` 로 이전에 쓰던 임시 글을 불러와 이어 쓰고(비회원은 `localStorage` 의 임시 글 식별키), "임시 저장"은 화면에 남아 계속 쓰며 "게시"하면 글 번호가 붙고 목록으로 이동한다.

## 형식 폴더와 화면 구상

| 폴더 | 형식 | 화면 구상 |
| :--- | :--- | :--- |
| `Default/` | 일반 | 제목·작성자·날짜 표 목록(List), 글 읽기(View), 아래에 댓글. |
| `Gallery/` | 갤러리형 | 대표 이미지 썸네일 격자 목록(List), 상세는 이미지를 크게 보기(라이트박스·넘겨보기). |
| `Forum/` | 포럼형 | **첫 게시글이 주제**가 되고, 그 글로 들어가면 **그 내부가 다시 하나의 게시 목록**을 가지는 형태 (포럼 목록 → 주제 → 주제 안의 게시 목록). 글타래 단위로 답글 수·조회 수·마지막 활동을 보여 주고 최근 활동순 정렬·상단 고정을 지원. |
| `Blog/` | 블로그 | 목록·보기 페이지 없이 **글 보기를 최신순으로 이어서 보이는 피드**(한 페이지 5개, 페이지 번호 5개씩). 글쓰기를 뺀 모든 처리(댓글은 포럼형)를 피드에서. 답글 없음. |
| `Manual/` | 메뉴얼 | **목록과 보기가 한 화면**. 맨 위 오른쪽 "목차" 버튼의 드롭다운 상자에 페이지 그룹 → 페이지 목차(카테고리가 있으면 위에 선택, 첫 항목이 기본), 그 아래에 선택한 글의 본문. 이전/다음 페이지 이동, 그룹 작성자·관리자의 페이지 순서 변경 모달, 검색 없음. 계획: `MANUAL_PLAN.md`. |
| `FAQ/` | FAQ | 보기 페이지 없이 **질문(Q)·답변(A) 카드 목록**. 가운데 제목·검색바·카테고리 목록(전체 + 카테고리) 아래에 카드, 최신 갱신순. 등록 화면은 질문·답변 글자 입력(줄바꿈은 br 로 저장). 계획: `FAQ_PLAN.md`. |
| `Survey/` | 설문 | 목록은 일반 게시물 목록. 보기에서 **미참여자는 설문 항목에 응답, 참여자는 결과(옵션별 득표수·비율)**. 글쓰기는 소개문 + 설문 항목(모달로 등록, 항목 최대 20개, 옵션 2~8개, 하나/여러 개 선택), 설문 기간·대상자 항상 사용. 계획: `SURVEY_PLAN.md`. |

현재 `Default/` 만 화면이 있습니다: `Index.cshtml`(상단: 아이콘·규칙 제목·글 수 배지와 오른쪽 검색 입력 그룹(화면만, 아직 동작 안 함) / 번호·제목·글쓴이·날짜·조회 표 / 아래: 페이지 이동과 글쓰기 버튼), `List.cshtml`(`/content/{규칙}/list` 로 같은 목록), `Write.cshtml`(글쓰기 UI — 규칙 설정에 따라 구성이 달라짐: 카테고리가 있으면 카테고리 선택, 공지글 옵션(`UseNotice`)이면 공지 체크, 제목은 입력 그룹이고 연관 링크(`UseRelatedLinks`)·게시 기간(`WriterPeriod`)·게시 대상(`WriterTarget`) 중 켜진 것이 있을 때만 끝에 더보기(⋮) 버튼과 메뉴가 나옴, 에디터, 태그 옵션(`UseTags`)이면 하단 태그 입력; 저장은 아직 동작하지 않음). 글쓰기 버튼은 쓰기 권한이 있을 때만 보입니다. 나머지 형식 폴더는 자리표시자 `Index.cshtml` 만 있고, 상세 등 나머지 뷰는 이후 작업에서 추가합니다.

갤러리(`Gallery/`): `Index`/`List` 는 대표 이미지 카드 격자 목록(`Index.cshtml(.scss)`, 일반 형식과 같은 `api/content/list`·같은 쿼리 상태, 한 페이지 12·24·36·48), `View` 는 일반 형식 글 보기에 첨부 이미지 캐러셀(`Carousel.cshtml(.scss)` — 큰 이미지·이전/다음·썸네일 줄·키보드 좌우·터치 밀기·전체 화면)을 제목줄 아래에 넣어 보여 주며, `Write`·`PostPassword`·`Manage` 는 일반 형식 화면을 그대로 쓴다(`Manage` 는 갤러리면 파일 탭을 없애고 첨부 사용·확장자·업로드/다운로드 권한·답변 권한·답글 허용·변경 기록·비공개·익명 항목을 숨기며, 기능 옵션 탭의 메뉴 구성 아래에 "파일 구성"(개수·파일별 용량·전체 용량)과 작고 옅은 안내 문구를 둠).

포럼(`Forum/`): `Index`/`List` 는 일반 형식 목록(`Default/Index`)을 쓰되 포럼이면 번호 열 없이 글쓴이·조회·마지막 댓글·활동(`UDate`, `common.ago` 상대 시간)을 보이고 글쓰기 버튼은 "새 토픽"(`NewTopic`). `Write`·`PostPassword`·`Manage` 는 일반 형식 화면 전달(`Write` 는 제목 "새 토픽", 공지 체크는 수정에서 비활성, `Manage` 는 답글 권한·답글 허용·댓글 좋아요·비공개·익명 숨김, 수정·삭제 허용은 토픽에만 적용한다는 안내). `View` 는 `Default/View` 를 쓰되 포럼 토픽(공지 제외)이면 이전/다음 글 없이 마지막 활동(`UDate`)·"최신 댓글로 이동"을 보이고 댓글 영역을 `Forum/Replies.cshtml(.scss)` 로 바꾼다: 댓글을 10개씩 `api/content/comments` 에서 받아 카드로 그리고(깊이 없이 `UDate` 최신순 한 줄, 부모가 있으면 부모 댓글에 대한 댓글 표시, 모든 댓글에 "N개의 댓글" 접기·[댓글] 버튼, 펼친 목록은 읽기 전용에 "게시물로 이동"), 쓰기·수정·1단에 댓글 달기는 `forumComment` 모달(`wwwroot/ts/modals/forumComment.ts`), 좋아요·변경 기록·삭제는 카드 안에서, 주소 `?jump=댓글번호` 는 그 댓글 페이지로 이동·강조. 공지 토픽은 기본 댓글 영역을 그대로 쓴다.

블로그(`Blog/`): `Index`/`List` 는 피드(`Index.cshtml(.scss)`) — 컨트롤러(`ContentController.FillFeedAsync`)가 목록 API 와 같은 처리(`ContentManager.ListPostsAsync`, 쿼리 `page`·`q`·`category`·`pending`, 크기는 서버가 5로 고정)로 쪽의 글을 고르고, 열 수 있는 글마다 글 보기 모델(`PostItemAsync` — 글 보기 화면과 같은 값, 조회수도 올림)을 만들어 `Model.Feed` 에 담는다. 화면은 글마다 글 보기(`Blog/View` → `Default/View`, `InFeed`)를 그대로 그려 본문·좋아요·공유·첨부·태그·연관 링크·수정·삭제·승인·변경 기록·이동·신고·포럼형 댓글(`Forum/Replies.cshtml`)을 모두 피드에서 처리하고, 글쓰기(새 글·수정)만 글쓰기 화면으로 간다. 피드 안의 글 보기는 게시판 제목줄·목록/글쓰기 버튼이 없고, 삭제하면 피드를 다시 읽으며, 댓글 영역은 접힌 상태(제목줄에 댓글 수)로 시작해 펼칠 때 처음 불러오고(블로그 댓글은 한 쪽 20개, 한 쪽뿐이면 번호 없음), 제목줄 오른쪽에 댓글 달기·글 편집·삭제 버튼을 접힘과 상관없이 항상 보인다(글 보기 아래 버튼줄에서는 뺌). 글 보기·댓글 스크립트는 자기 요소(`document.currentScript` 앞 요소) 안에서만 찾아 한 페이지에 여러 개가 함께 동작한다. 열 수 없는 글은 제목과 잠금 표시만, 비회원 글은 비밀번호 확인 화면으로 가는 제목 링크만 보인다. 페이지·검색·카테고리·미승인 보기는 주소 쿼리로 다시 연다. 글 보기 주소(`/content/{규칙}/view/{번호}`, `/content/view/{글 키}` — 통합 검색·알림·댓글 번호 이동 등)로 들어오면 별도 보기 페이지 대신 그 글 하나만 담은 피드(`SinglePost`, `ContentController.SinglePostFeedAsync`)를 보이고 목록 버튼으로 전체 피드로 가며, `?jump=댓글번호` 면 댓글을 펼쳐 그 댓글로 이동한다. `Write`·`PostPassword`·`Manage` 는 일반 형식 화면 전달(`Write` 는 공지 체크가 수정에서 비활성, `Manage` 는 포럼과 같은 항목을 숨김). 게시판 형식 목록(신규 게시판 선택 등)에서는 포럼 바로 다음에 보인다(`BoardAccess.BoardTypes` 순서, `ContentTypes` 값은 DB 에 정수로 저장돼 끝에 추가).

## 형식 추가 후보 (논의됨, 아직 `ContentTypes` 에 없음)

대부분 규칙·기능 옵션을 더하면 기존 형식으로 지원할 수 있어 보이며, 화면 모양이 확실히 다른 것만 형식으로 추가합니다.

- `Page` — 목록 없이 한 문서만 보이는 단일 페이지 (회사 소개 등). 가장 먼저 필요해 보임.
- `Faq` — 질문을 누르면 답이 펼쳐지는 아코디언.
- `Archive` — 첨부 파일 중심 표(파일명·크기·다운로드 수).
- `Calendar` — 월 달력과 일정 목록.
- `Inquiry` — 작성자와 관리자만 보는 1:1 문의 접수형, 처리 상태.

형식을 추가하려면: ① `BitPlus/Data/Content/ContentTypes.cs` 에 값 추가 ② `Views/Content/{값}/Index.cshtml` 추가 ③ 컨텐츠 규칙 화면의 형식 표시명 리소스(`ContentType{값}`, en/ko) 추가.

사이드 패널(`SidePanel.cshtml`)은 게시판 설정의 사이드 구성을 따른다: 감춤이면 페이지 틀(`Index.cshtml`)이 그리지 않고(모바일 사이드 버튼도 잠김), 우측이면 `div.pageWrap.sideRight` 로 본문 오른쪽에 두며, 패널 내용은 위젯 페이지 `side`(연결 메뉴가 있으면 `side@{메뉴 키}`)의 쌓기형 위젯이며, 위쪽 메뉴 트리도 컨텐츠맵 위젯(`Views/Widgets/ContentMap`, 한 패널에 하나)이라 같은 위젯 편집(톱니)에서 순서·추가·삭제를 함께 관리한다. 컨텐츠맵 위젯은 연결 메뉴가 있으면(사용 중인 메뉴일 때) 제목 자리에 그 메뉴 이름, 트리에 그 하위 메뉴를 보여 주고(없으면 컨텐츠맵 트리, 제목 Contents), 신규 게시판 + · 게시판 설정 톱니는 컨텐츠 페이지 영역(게시판·포탈)에서만 보인다. 사이트의 게시판 설정 화면(`/content/manage/{규칙}`)도 같은 구성을 따른다(관리자 콘솔 설정 화면은 관리자 레이아웃이라 해당 없음).
